<objective>
Replace all throwaway HTTP clients with a single persistent session client on the Deezer struct, add browser User-Agent to all API calls, and increase GW timeout to 30s.

Purpose: The #1 bug source — kyoku-dl creates fresh http.Client per GW call, losing server-set cookies. This causes media API failures because session cookies accumulated during getUserData are lost. Streamrip uses one `requests.Session` for everything.

Output: A single `http.Client` with `cookiejar.Jar` on the Deezer struct, initialized during auth, used for ALL API calls (GW, public, media). Browser UA on all requests.
</objective>

<task type="auto">
  <name>Task 1: Create persistent session client with cookie jar and browser UA</name>
  <files>provider/deezer/deezer.go, provider/deezer/auth.go</files>
  <action>
  **In `deezer.go`:**

  1. Add a `browserUA` constant: `"Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36"` (modern Chrome UA, not the ancient Chrome 79 from streamrip).

  2. Change `DefaultTimeout` from `10 * time.Second` to `30 * time.Second` (matching streamrip's timeout for GW calls).

  3. In `New()`: Initialize `httpClient` with a `cookiejar.New(nil)` and `Timeout: 30 * time.Second`. This replaces the bare `&http.Client{Timeout: DefaultTimeout}`. The cookie jar allows the client to accumulate and replay cookies across all API calls.

  4. Add a method `initSessionClient(arl, sessionID string)` on `*Deezer` that:
     - Creates a new `cookiejar.New(nil)`
     - Sets ARL cookie on `https://www.deezer.com` domain
     - Sets `sid` cookie if sessionID is non-empty
     - Creates a new `http.Client` with this jar, `Timeout: 30 * time.Second`
     - Assigns it to `d.httpClient`

  5. Refactor `gwAPICall()`:
     - Remove the per-call `cookiejar.New` and `gwClient` creation (lines ~1025-1029)
     - Use `d.httpClient` directly instead of `gwClient`
     - Remove manual cookie attachment (`req.AddCookie` lines ~1017-1022) — the cookie jar handles this automatically
     - Add `req.Header.Set("User-Agent", browserUA)` before the request
     - Remove the `output=3` query param (streamrip doesn't send it, it's unnecessary)

  6. Refactor `publicAPICall()`:
     - Change from `d.httpClient.Get(fullURL)` to creating an `http.NewRequest("GET", ...)` so we can set headers
     - Add `req.Header.Set("User-Agent", browserUA)` before the request
     - Use `d.httpClient.Do(req)` instead of `d.httpClient.Get()`

  7. Refactor `resolveMediaURL()`:
     - Remove the manual cookie attachment lines (`req.AddCookie` for arl and sid)
     - Remove the per-call `mediaClient := &http.Client{Timeout: 30 * time.Second}` 
     - Use `d.httpClient` instead of `mediaClient` (the persistent client already has the cookies and the 30s timeout)
     - Add `req.Header.Set("User-Agent", browserUA)` before the request

  **In `auth.go`:**

  8. Modify `InitSession()` to also return the populated cookie jar or to accept a `*Deezer` and initialize its client directly. The cleanest approach:
     - Add a new method `(d *Deezer) InitSessionFromARL(arl string) error` that:
       a. Calls `d.initSessionClient(arl, "")` to set up the persistent client with ARL cookie
       b. Uses `d.httpClient` (which now has the ARL cookie via jar) to call `deezer.getUserData` 
       c. Parses the response to extract `checkForm`, `license_token`, user caps, `sid`
       d. Updates `d.auth` with the extracted values
       e. The cookie jar on `d.httpClient` now has ALL cookies from the getUserData response (ARL + sid + any others the server set)
     - Keep the existing `InitSession(arl string) (*Auth, error)` function as a standalone helper (used by `auth login` CLI command), but have it create a temporary client internally
     - Update `EnsureAuth` to call `d.InitSessionFromARL` when the Deezer struct is available

  9. Update `SetAuth()` in `deezer.go` to also call `d.initSessionClient(auth.ARL, auth.SessionID)` so the persistent client is initialized when auth is set programmatically.

  **Key principle:** After this change, there should be ZERO places in the codebase that create a new `http.Client` for Deezer API calls. Every API call (GW, public, media) goes through `d.httpClient`.
