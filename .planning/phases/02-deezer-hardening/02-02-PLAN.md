Add CSRF token auto-refresh on GW API errors, rate limit handling on public API, and license capability pre-check before requesting stream quality.

Purpose: These are the top 3 error-handling gaps identified in the streamrip comparison. Without them, long sessions fail on CSRF expiry, burst API calls get permanent errors on rate limits, and users with free/HQ accounts get cryptic media API errors when requesting FLAC.

Output: Self-healing GW API calls, automatic rate limit backoff on public API, and early failure with clear messages on license mismatch.
</objective>

<task type="auto">
  <name>Task 1: Add CSRF token auto-refresh and rate limit handling</name>
  <files>provider/deezer/deezer.go, provider/deezer/auth.go, provider/deezer/types.go</files>
  <action>
  **In `types.go`:**

  1. Change `GWResponse.Error` from `[]interface{}` to a proper type. The GW API returns errors as a JSON object (map), not an array. Change to:
     ```go
     type GWResponse struct {
         Error   map[string]string `json:"error"`
         Results json.RawMessage   `json:"results"`
     }
     ```
     This makes error checking clean: `gwResp.Error["VALID_TOKEN_REQUIRED"]` instead of iterating over `[]interface{}`.

  2. Add a `PublicAPIError` struct for public API error responses:
     ```go
     type PublicAPIError struct {
         Error struct {
             Type    string `json:"type"`
             Message string `json:"message"`
             Code    int    `json:"code"`
         } `json:"error"`
     }
     ```

  **In `auth.go`:**

  3. Add a `(d *Deezer) refreshCSRFToken() error` method that:
     - Calls `deezer.getUserData` using the persistent `d.httpClient` (which already has the ARL cookie on its jar)
     - Parses the response to extract the new `checkForm` value
     - Updates `d.auth.APIToken` with the new value
     - Also refreshes `d.auth.LicenseToken` and capability flags while we're at it
     - If the getUserData call itself fails (ARL expired), return error — don't retry infinitely

  **In `deezer.go`:**

  4. Refactor `gwAPICall()` to handle CSRF token expiry:
     - After parsing `GWResponse`, check if `gwResp.Error` contains key `"VALID_TOKEN_REQUIRED"` or value `"Invalid CSRF token"` (streamrip checks for `"invalid api token"` string match)
     - If detected: call `d.refreshCSRFToken()`, then retry the same GW call ONCE (prevent infinite loop)
     - Use a `retried bool` parameter or wrap in a helper to prevent more than 1 retry
     - Update the existing error checking block (lines ~1052-1063) to use the new `map[string]string` type instead of iterating `[]interface{}`

  5. Refactor `publicAPICall()` to handle rate limits:
     - After reading the response body, check if the response contains a Deezer error (parse into `PublicAPIError`)
     - If error code is 4 or 700 (rate limit): sleep 5 seconds, retry ONCE
     - Log the retry in debug mode: `"Rate limited, retrying in 5s..."`
     - Use a retry counter to prevent infinite loops (max 1 retry, matching streamrip)
  </action>
  <verify>
  - `go build ./...` passes
  - `go vet ./...` passes
  - `grep "VALID_TOKEN_REQUIRED\|invalid api token\|Invalid CSRF" provider/deezer/deezer.go` shows CSRF detection
  - `grep "refreshCSRFToken" provider/deezer/auth.go` shows the refresh method
  - `grep "rate.limit\|Sleep\|code.*700\|code.*4" provider/deezer/deezer.go` (case-insensitive) shows rate limit handling
  </verify>
  <done>
  - GW API calls auto-refresh CSRF token on "invalid api token" / "VALID_TOKEN_REQUIRED" error and retry once
  - Public API calls detect rate limit (error codes 4/700), sleep 5s, and retry once
  - GWResponse.Error is a proper map[string]string instead of []interface{}
  - refreshCSRFToken method re-fetches checkForm via getUserData
  </done>
</task>

<task type="auto">
  <name>Task 2: Add license capability pre-check before stream quality request</name>
  <files>provider/deezer/deezer.go</files>
  <action>
  In `getStreamURL()`, BEFORE calling `resolveMediaURL` or building the legacy CDN URL, add a license pre-check:

  1. After determining `actualQuality` (the quality after file-size fallback), check against the user's account capabilities stored in `d.auth`:
     - If `actualQuality == "FLAC"` and `!d.auth.CanStreamLossless`: 
       - If `d.auth.CanStreamHQ`: fall back to `"MP3_320"` and log `"Account cannot stream lossless, falling back to MP3_320"`
       - Else: fall back to `"MP3_128"` and log `"Account cannot stream lossless or HQ, falling back to MP3_128"`
     - If `actualQuality == "MP3_320"` and `!d.auth.CanStreamHQ`:
       - Fall back to `"MP3_128"` and log `"Account cannot stream HQ, falling back to MP3_128"`

  2. This check must happen AFTER the file-size-based fallback (which checks FILESIZE_FLAC/FILESIZE_MP3_320) but BEFORE the media API call. The order is:
     a. File-size fallback (existing) — "does this track have FLAC?"
     b. License pre-check (new) — "can this account stream FLAC?"
     c. Media API call (existing) — "give me the stream URL"

  3. Use `fmt.Fprintf(os.Stderr, ...)` for the warning messages (consistent with existing warning style in auth.go), or use debug logging if `d.debug` is true.

  4. Update the `StreamInfo.ActualQuality` to reflect the post-license-check quality so the TUI shows the correct quality.
  </action>
  <verify>
  - `go build ./...` passes
  - `go vet ./...` passes
  - `grep "CanStreamLossless\|CanStreamHQ" provider/deezer/deezer.go` shows the pre-check in `getStreamURL`
  </verify>
  <done>
  - License capability is checked before requesting stream quality
  - FLAC falls back to MP3_320 or MP3_128 based on account capabilities
  - MP3_320 falls back to MP3_128 if account lacks HQ
  - Warning message logged when quality is downgraded due to license
  - TUI shows actual (post-license-check) quality, not requested quality
  </done>
