<objective>
Extract genre from album metadata and map copyright from GW song data to track metadata, filling the remaining metadata gaps identified in the streamrip comparison.

Purpose: Deezer has genre and copyright data that kyoku-dl ignores. Without this, downloaded files lack genre tags unless MusicBrainz enrichment is enabled, and copyright is never tagged despite being available in the GW song data.

Output: Genre populated from Deezer album response, copyright from GW song data, both flowing into the tagging pipeline.
</objective>

<task type="auto">
  <name>Task 1: Extract genre from album and map copyright from GW song data</name>
  <files>provider/deezer/deezer.go, provider/deezer/types.go</files>
  <action>
  **In `types.go`:**

  1. Add `ExplicitLyrics` field to `TrackResponse` (the public API returns this):
     ```go
     ExplicitLyrics bool `json:"explicit_lyrics"`
     ```
     This is for future use — we won't map it to provider.Track yet since Track doesn't have an Explicit field, but having it in the type means we can use it later.

  **In `deezer.go`:**

  2. In `GetAlbum()`, extract genre from the album response and apply it to all tracks:
     - After the existing track enrichment loop, add genre extraction:
       ```go
       // Extract primary genre from album
       albumGenre := ""
       if len(resp.Genres.Data) > 0 {
           albumGenre = resp.Genres.Data[0].Name
       }
       ```
     - In the track enrichment loop, set `track.Genre = albumGenre` for each track (only if MusicBrainz hasn't already set it — but since MB enrichment happens later during download, we always set it here; MB will override if enabled)

  3. In `DownloadTrack()`, also extract genre from the album response. The existing code already fetches album data (`d.publicAPICall("/album/" + ...)`). After parsing `albumResp`, add:
     ```go
     if len(albumResp.Genres.Data) > 0 {
         track.Genre = albumResp.Genres.Data[0].Name
     }
     ```

  4. Map copyright from GW song data. The `GWSongData.COPYRIGHT` field is already in the type but never mapped. The best place to do this is where we have both `songData` and `track` in scope. Two locations:

     a. In `DownloadTrack()` — after getting stream info (which fetches songData internally), we need to surface the copyright. The cleanest approach: add `Copyright` field to `StreamInfo`:
        ```go
        type StreamInfo struct {
            // ... existing fields ...
            Copyright string
        }
        ```
        Then in `getStreamURL()`, set `streamInfo.Copyright = songData.COPYRIGHT`.
        Then in `DownloadTrack()`, set `track.Copyright = streamInfo.Copyright`.

     b. In `DownloadAlbum()` — same pattern: after getting stream info for each track, set `album.Tracks[i].Copyright = streamInfo.Copyright` before creating the download task.

  5. Verify that `provider.Track.Copyright` (already defined in provider.go) and `provider.Track.Genre` (already defined) flow into the tagging pipeline. Check `provider/tagger.go` to see if these fields are already used in `TagAudioFile`. If not, this is a separate concern — just ensure the Track struct is populated. (The Genre and Copyright fields are already on Track — the tagger should already handle them if they're non-empty.)
  </action>

  </verify>
  <done>

  - Both DownloadTrack and DownloadAlbum populate genre and copyright
  - ExplicitLyrics field added to TrackResponse for future use
  </done>
